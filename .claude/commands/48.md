Opus 4.8 tuning checklist:

- Give it room to reason before answering on genuinely hard/multi-step tasks — don't over-constrain the reasoning path, just the output.
- State the goal and success criteria explicitly and early; Opus performs better with a clear target than with implicit expectations.
- Use structured sections (headers, bullet specs) for multi-part requirements rather than one dense paragraph.
- Be explicit about output format if it matters (length, structure, code vs. prose) — Opus won't guess a format you care about.
- Don't pad with unnecessary caveats or hedging language in the prompt itself — say what you want directly.
- Preserve every concrete constraint and piece of context from the spec; polishing tone must not drop information.
